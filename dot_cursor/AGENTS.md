# Comment Style

Keep comments terse. A comment should label *what* something is, not describe *how* or *why* at length. If a paragraph is needed, it belongs in commit messages, PR descriptions, or docs — not inline.

## Code

- Don't narrate what the code does (`// increment counter`, `// import the module`). The code already says that.
- Only add a comment when it conveys non-obvious intent, a constraint, or a trade-off the code can't express.
- Never explain in code comments the *change* you are making — that's what the commit message is for.

## Config files (`.gitignore`, `.chezmoiignore`, `.chezmoiremove`, `.dockerignore`, `.editorconfig`, etc.)

- Section labels are fine and helpful: `# Audio files`, `# Python venv`, `# nvim plugin specs`.
- No multi-line descriptions, no rationale paragraphs, no "intentionally NOT added because…" notes. If a rationale is essential, put it in the commit message instead.

## ✅ Good

```gitignore
# Build output
dist/
build/

# Editor
.vscode/
.idea/
```

```ts
const MAX_RETRIES = 3
```

## ❌ Bad

```gitignore
# Build output (these directories are generated by webpack and contain
# the bundled JavaScript and CSS. We don't want them in version control
# because they're large and can be regenerated from source.)
dist/
build/
```

```ts
const MAX_RETRIES = 3 // maximum number of retries before giving up
```

# Token Efficiency

Default concise. Preserve decisions, caveats, verification results, and file references.

## Context

- Prefer targeted context: `rg`, `Glob`, `ReadFile` ranges, and semantic search for broad questions.
- Avoid broad folder dumps, whole-file reads, and large terminal output unless needed.
- Use subagents for noisy exploration when isolated context is cheaper than loading everything into the main chat.
- Use Max Mode, many MCP servers, broad `@folder` context, and parallel agents only when the task needs them.

## Shell

- Prefer quiet, targeted commands.
- When RTK is available, let it compact noisy command output.
- For failed commands, inspect saved full output before rerunning expensive commands.
